# Nexora v0.5.0-preview · 第一阶段

基线：v0.4.1-preview（ff70b7f）。本阶段只增加业务语义模型及策略定义，不接入 Agent 或修改 manifest、已发布版本、原目录、外部意图库或其他集成。

## 模型

- QueryKey：模块、对象、指标、账期、动态参数类型、账户；以现有 Profile 和原目录为来源，索引不可变，语义重复拒绝构建。
- Capability：注册能力 ID、原 Intent、语义量纲、是否要求原生目标。量纲不是实际返回单位；同量纲的缴费/账单、设定/检测/环境温度、阶梯额度/表读数也不能合并。
- PolicyKey：模块、明确对象、查询目的、账户及账期；不以整句为键。无规则返回 None，不静默换账户、日期或设备。
- Scene：主要查询、补充查询、停止条件、必要说明。只引用注册能力，最多4项；优先已有聚合能力。停止条件本阶段仅是契约，后续执行层根据真实结果判断，不解析文本猜测状态。

## 默认策略边界

无实物单位的燃气剩余可理解为金额；明确实物单位则说明不能获取实际剩余气量，提供一、二阶梯剩余额度（不能当作表内余量）。未指定电费账户时，后续 Context Resolver 可按已确认的主账户默认规则补全 j，但本层不自动替换明确账户；次账户未配置或同名时后续必须校验，不转为主账户。明确日期不得被场景默认覆盖。灯具状态以灯组口径描述，不代替物理灯泡数量；环境亮度与灯具亮度不同。

关机补充环境温度只在用户询问空调温度且确认无运行参数时使用，标记为独立房间传感器，非空调检测温度。明确控制与混合请求不由本模型授权或执行。无效/缺失源数据不等于正常状态。

## 复核

对全部443项业务能力进行唯一分类及精确反向查找；检查34项动态参数、45项灯具原生目标；检查场景引用、预算、账号/账期隔离及错误定义拒绝。自动化回归仍保留旧版运行时测试。后续阶段才引入口语解析、纠错、上下文、执行与回复整合，当前不宣称自然语言准确率或性能目标达成。

复核补强：停止条件仅控制补充查询，不能跳过主要查询；跨域补充只允许指定房间的独立温度、阳台环境与灯光状态，并要求明确来源说明；其他跨对象或跨账户场景拒绝注册。已知 Intent 缺失 Slots 不能静默忽略。
