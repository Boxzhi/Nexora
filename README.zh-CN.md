## 场景菜单（v0.5.6-preview）

help 为唯一公开菜单，保留150项业务场景（水电气65、灯光37、家电24、全屋状态24），根据实际注册能力动态显示。原443项注册只读能力及单项自然语言查询完整保留，旧数字路径仅供内部回归。升级后先发送 help，再选择数字。明确命中注册场景的自然语言与数字菜单共享查询计划，不依赖备用 AI；不猜测未注册或存在歧义的表达。菜单场景最多12项、2路并发、12秒执行预算，普通结构化计划仍最多4项。共享日期只输入一次，保留数据缺失及状态限制，支持同会话已注册场景重复查询和明确账期/账户范围切换。

## v0.5.6-preview 更新

- 扩展带明确对象和业务范围的场景短语，包括最近燃气缴费记录与年度缴费统计。736条无歧义注册短语均通过模拟 Agent 执行审计，不代表任意自然语言覆盖；精确单项指标查询仍独立。
- 仅对 conversation_id 以 wechat: 开头的本地只读查询结果，将单换行转换为 Unicode U+2028。段落、菜单、非微信渠道及备用 AI 回复保持不变；不修改 CN IM Hub。
- 合并一致的本期账单月份、空调关机限制和人体感应/光照数据；优化温湿度统计、全屋概况及灯具长名单排版。两处卫生间灯具名称仅调整场景展示，不改底层能力 ID。冲突、缺失及有效监测范围继续保留。
- 真实微信中的“全屋照明概况”曾出现绕过 Nexora 的迹象，直接调用 Agent 正常。外部处理位置尚未确认，F10 不在本版已修复范围；绕过 Nexora 的回复也不会经过本版格式化。

安装：HACS 自定义仓库（Integration），或替换 custom_components/nexora。原 Nexora 集成配置保留，重启 Core 一次后验证。自定义目录 /config/nexora/catalogs/ 支持 JSON/YAML，重载集成生效。详见 [注册协议](docs/catalog.md)。

Nexora 独立运行于 HA Conversation Agent 标准入口，不要求升级 CN IM Hub 或 AI Hub，也没有跨集成私有协议。路由顺序为菜单、参数与业务追问，明确歧义检查，原生严格识别与本地语义一致性校验，再按需执行、澄清或交给现有备用代理。未匹配的家庭实时查询、缺少上下文、取消查询及识别出的查询与控制混合请求在本地处理。Nexora 自身仅执行经校验的只读查询；普通知识问答及设备控制指令沿用备用代理配置及权限。家庭实时查询保护是规则识别，不是权限沙箱。AI 会话与本地状态分离，备用对话超时60秒。仅针对 HA Core 2026.11.3 接口开发，v0.5.6-preview 真实环境仍待验收。

验收脚本独立运行，不随集成安装：scripts/probe.js 为专项验收，scripts/full_probe.js 仅遍历 help 场景菜单。参见 [查询规划](docs/query-planner-v050.md) 与 [验收说明](docs/preview-acceptance.md)。

## 本地智能查询决策

保留原有标准句式、日期、菜单及严格只读路径。新增结构化语义解析、审定错别字自动纠正、默认指标、场景与多项只读查询。每次计划最多4项注册查询，计划内最多2路并发、执行预算12秒（原生识别与映射准备另计）。回复保留实际数据、账户和对象信息、部分失败及数据缺失说明。无外部模型、新依赖、数据库或轮询。未识别表达不随意猜测，结构化目录无法验证时保留旧路由；不是任意中文理解或权限沙箱。

## 综合查询与连续追问（v0.5.2）

修复水电气综合余额、欠费、充值检查和数据更新时间的指标映射。主住所与全部账户可明确切换，并保留查询指标；账户范围不等于历史账期或次住所电费账户。支持“分别”“各自”等逐账户查询，但不推算未注册的总金额。缺少有效上下文的欠费、充值等实时追问及不支持的家庭账户查询在本地提示，不交给 AI 猜测。年度基础电费统计与历史正式账单累计区分，连续查询保留对应指标含义。补强全屋环境聚合、灯光状态与列表、洗衣机电源和运行状态、设备水温及房间温度的语义边界。原443项注册能力保持不变。反向审计衡量固定注册问句的结构化可达性，不代表任意口语覆盖率。

## 回复质量及诊断

统一 Nexora 内部只读查询的回复格式化，菜单与备用代理回复保持不变。按账户、灯具、设备及房间分组组织已验证的回复，确认信息一致才去重；保留来源、统计范围、数据缺失、状态限制与冲突。已验证的洗衣进度、净水器、空调关机温度及阳台光照场景支持合并；不认识的格式、部分缺失或不一致的结果保留原文。仅移除明确物理量的冗余小数尾零，保留金额精度及数据时效等说明。query_quality 单独统计部分有效、缺失、状态和能力限制，不等于路由成功次数。先发送 help 正常刷新目标映射，再从 HA Nexora 集成页面下载诊断，检查隐藏原因、灯具模式及元数据来源。诊断不包含家庭实体 ID、对话原文或绑定模板，不触发新查询。未核实的实际隐藏能力不强制恢复。

参见 [v0.5.1 回复质量](docs/response-quality-v051.md)。

## 动态菜单

443 为注册能力基线，不再强制展示全部项目。灯具能力从本地严格识别的目标及 supported_color_modes 判断；已确认不支持的亮度、色温隐藏，设备关机、离线或暂时不可用不会移除其已确认支持的能力。目标映射按需缓存5分钟，状态属性在菜单生成时读取，无轮询。已知 Home v1.0.1 / Appliance v1.0.0 模板通过静态 AST 提取原生绑定，Lights v1.1.0 延续严格目标识别，无需额外文件。/config/nexora/bindings.yaml（可选）仅用于人工覆盖，null 强制隐藏；修改人工覆盖后重载 Nexora。未知模板、临时离线或实体缺失保持显示。

支持 1.2.1 这类相对当前菜单的数字路径，不能跨越查询或参数输入，无效路径不改变当前菜单。普通菜单不再显示示例句。追问覆盖由 Nexora 自身成功执行的水电气、灯光、家电、全屋状态注册能力，支持受控对象、指标、账期、账户切换、指定日期继承及明确澄清选项。其他集成直接执行的 Intent 不经过 Nexora，因此无法同步或清理其旧上下文；切换查询路径后应明确账户和指标，不能保证省略式跨集成追问正确。查询上下文5分钟、菜单10分钟、AI 会话映射30分钟。支持已注册动态日期参数继承，但 AI 工具查询不共享业务上下文。全量脚本分别报告可见查询执行和隐藏项复核，不把隐藏自动算作失败或通过。

自动提取仅匹配已验证的模板结构，绑定字典内容允许变更。Intent Script 重新加载后，下次交互自动检测源码变化，不需要重载 Nexora，不执行探测查询、不新增轮询、不公开家庭实体。Home 原版窗户分支尚未实现，因此自动隐藏；马桶盖传感器保留独立语义。未来修改窗户查询逻辑后，不匹配已知结构则保守显示。水电气维持原行为。
